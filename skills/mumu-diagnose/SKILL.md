# mumu-diagnose · 真机结论失真排查

## 用途

真机验证的成本高，所以最容易犯的错是「跑出来一堆 FAIL，直接去改产品代码」。
实际情况里，相当一部分 FAIL 来自前置条件（旧脚本、旧页面、没注入、判据不成立）。
本技能给出一条固定的四步排查路径，**先证明这轮数据是真的，再讨论代码对不对**。

## 何时用

- 全 FAIL，但桌面回归是过的
- 一条断言都没上报（`!! 一条断言都没上报`）
- `env.version` 是 `none`、或与 `dist` 不一致
- 断言全过，但截图/录屏看着明显不对
- 同一份代码两次跑出相反结果
- 退出码非 0，但控制台里没有 FAIL 行

## 输入

- 本轮现场：`=== 环境 ===` 那几行、`=== 断言 ===` 的 FAIL 明细、`diag` 时间线、退出码
- `.tmp/report.log` 里本轮 `run` 对应的原始行数

## 输出

- 一句话判定：**数据可信 / 数据不可信（原因）**
- 处置动作：换版 / 重开页面 / 改判据 / 修产品代码

## 依赖

全部其它技能（`mumu-device` / `mumu-deploy` / `mumu-harness` / `mumu-verify`）。

## 四步排查（按顺序，别跳）

### 第 1 步：版本对齐了吗

看 `env` 行：

```
脚本版本: v0.1.88  ·  期望 v0.1.88  ·  视口 360×520 dpr=3
```

- `v...none` 或不一致 → **数据不可信**，走 `mumu-deploy`
- `none` 的两种典型原因：content 存成了 BLOB（脚本抛 `Unable to convert BLOB to string`）、
  或者页面根本是旧缓存（加载的是上一轮那份没注入脚本的 HTML）
- 视口/`dpr` 明显不对（比如 dpr=1、宽 800+）→ 不是 Via 的 WebView，测的不是目标环境

这是唯一能一眼判死的检查，**永远先看它**。

### 第 2 步：脚本注入了吗

- `__vv` 不存在 / `onerror` 里 `Unable to convert BLOB to string` → 回 `mumu-deploy`
- `__vv` 存在但功能不生效 → 看 `VV.version`，再怀疑功能
- 页面里有 `via-vp: already loaded` → 同一份脚本被注入两次，第二个实例被 guard 截断。
  这不是故障，但会影响「脚本执行成本」类测量（对照组只能量到预解析，量不到执行）

### 第 3 步：页面还是旧的吗

Via 的 WebView **按 URL 路径**命中缓存：`?t=` 时间戳、`Cache-Control: no-store`、`Pragma` 全都不管用。

判别方法：看断言名/`diag` 字段与你刚写的代码是否对得上。对不上就是旧页面。

处置：

- 每轮用一次性路径后缀（`xxx-r<时间戳>.html`），并在 `serve.mjs` 加别名映射
- 加了映射**必须重启 `serve.mjs`**，规则只在启动时生效，否则新路径直接 404
- UI 更新脚本那条路同理：`download_url` 按路径命中，旧路径永远拿旧版

### 第 4 步：断言与采样方式成立吗

前三步都干净，才轮到「是不是判据本身错了」：

- **单点采样**：真机时序抖动大，睡固定时长后断言必然时对时不对 → 改采样式
- **观察窗口太短**：真机比桌面慢一截，窗口按桌面经验给会一直差一点
- **判据落在会自适应变化的量上**：码率档、缓冲深度、并发数属于「按设计会变」的量，
  拿它当劣化断言会产出假 FAIL（案例见 `mumu-measure/references/method.md` 第二条）
- **窗口内窗口外不一致**：`?wait=` 拉长窗口后结果变了 → 说明只是没等够，不是代码问题

## 判定口径

| 观察到 | 结论 |
| --- | --- |
| 版本不一致 / `none` | 数据不可信，什么都没证明 |
| 版本对，但一条 `ok` 都没有 | 数据不可信，报的是「没跑起来」不是「功能坏了」 |
| 版本对、断言全 FAIL 且 FAIL 内容彼此矛盾 | 高度怀疑旧页面或注入时机 |
| 版本对、FAIL 集中在某个场景 | 真问题，看 `diag` 时间线定位 |
| 断言全过但截图不对 | 截图不可信（浮层不进合成帧），以 DOM 断言为准 |
| 两次结果相反 | 采样方式问题，先改判据再谈代码 |

详细症状对照表（含每条的历史成因与一行修复命令）见 `references/symptom-table.md`。

## 反模式

- ❌ 看到 FAIL 就去改产品代码 —— 先花 30 秒看 `env` 行
- ❌ 把 `mumu-loading` / `mumu-slow` 的「版本不一致，本轮无效」当成报错跳过
- ❌ 用 `adb screencap` 的截图否掉页内 DOM 断言（浮层本来就不一定进系统截图）
- ❌ 把 `via-vp: already loaded` 当故障去改加载逻辑
- ❌ 反复 `am start` 刷新页面 —— 会新开后台标签并被 Chromium 冻结，现象比原来更怪
